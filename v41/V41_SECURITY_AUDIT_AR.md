# Link Pharma v41 — تدقيق أمني وإصلاحات

تم التعامل مع المشروع كمنصة React/Firebase معرضة لمهاجم يملك حساباً عادياً أو وصل إلى المستودع. لم يتم اعتبار وجود Firebase Web API key سراً؛ الحماية الحقيقية تعتمد على Firebase Auth وFirestore Rules وقيود Google Cloud.

## الثغرات التي عولجت

### تجاوز التجربة والاشتراك — خطورة عالية
كانت قاعدة إنشاء المستخدم تسمح للعميل بإنشاء ملف صيدلية بحالة `active` ومدة تصل إلى سنة. أُغلقت هذه الثغرة في `firestore.rules`: التسجيل الذاتي يقبل `trial` فقط، مع مدة قصوى محدودة، بينما منح الاشتراك المدفوع يجب أن يتم من مسار إداري موثوق. أضيف اختبار Rules يمنع إنشاء `active` ذاتياً.

### التوجيه الخاطئ وصلاحية المدير المحلية
تم منع السباق الذي كان يعالج ملف المستخدم قبل اكتمال فحص صلاحية المدير. كما لم يعد fallback أو كاش `localStorage` قادراً على منح دور مدير أو اشتراك نشط محلياً، ويُمسح كاش الملف عند تسجيل الخروج. تظل قواعد Firestore هي مصدر التفويض الفعلي.

### تزوير الطلبات وتلوث البيانات
أضيفت في قواعد الطلبات قائمة حقول مسموحة وحدود للحجم، وتحقق من رقم الطلب والصيدلية والمورد والقيمة والحالة وقائمة الأصناف. كما أصبح فشل كتابة الطلب إلى Firestore يُعاد للواجهة بدلاً من حفظ نجاح محلي مضلل.

### سجلات المستخدمين غير المقيدة
أضيفت قيود schema وحجم أساسية للاقتراحات وسجل النشاط وملفات presence، مع منع الحقول الإضافية في هذه المسارات.

### سلسلة البناء
أضيف بناء v40 وv41 إلى GitHub Pages واستخدام `npm ci` في النسختين الجديدتين اعتماداً على lockfile. يجب لاحقاً تثبيت GitHub Actions على SHA وتفعيل Dependabot/Dependency Review في إعدادات المستودع.

## ما يجب ضبطه خارج الكود

يجب نشر `firestore.rules` فعلياً إلى مشروع Firebase الإنتاجي؛ وجود الملف في GitHub وحده لا يغير القواعد المنشورة. كما يجب تقييد Firebase Browser API key حسب HTTP referrers وواجهات APIs المطلوبة، تفعيل App Check وquotas والتنبيهات، ومراجعة Authorized Domains.

لا يحتوي المستودع المفحوص على service-account private key أو client secret. إذا وُجد أي سر حقيقي خارج الملفات المفحوصة في تاريخ Git، يجب تدويره من مزود الخدمة وعدم الاكتفاء بحذفه من آخر commit.

## التحقق

تم تشغيل `npm run lint` و`npm run test:rules:emulator` و`npm run build` على v41 بنجاح. تحذيرات Vite الخاصة بـ`__dirname` وتحذير Node/GitHub Actions لا تمنع البناء لكنها تحتاج تحديثاً دورياً.
