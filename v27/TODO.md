# متابعة v25

## منجز في المصدر
- [x] إضافة طلب ربط المستودع من الملف الشخصي وإدارة الطلبات من لوحة الإدارة، مع صلاحيات منفصلة للرفع والعروض والجدولة.
- [x] مساحة مندوب منفصلة ومقيدة بمستودع واحد؛ لا سلة صيدلية ولا إنشاء طلبات شراء.
- [x] استيراد Excel للمورد المرتبط مع دعم العروض، سجل قبل/بعد ومنفذ التغيير، ومنع المندوب من إنشاء أصناف أو التراجع عن دفعات المدير.
- [x] زر «عرض الصنف» وصفحة تفاصيل تعرض العروض المسموح بها وآخر تغييرات الأسعار حسب المورد.
- [x] مركز مهام على لوحة الإدارة يوجه إلى الطلبات المعلقة والأسعار القديمة والجداول الناقصة/القديمة وأخطاء الاستيراد وطلبات المندوب والاعتمادات.
- [x] صفحة تدقيق قابلة للبحث والتصفية حسب المنفذ/العملية/التاريخ، مع تصدير CSV وعرض التفاصيل السابقة/اللاحقة للسعر.
- [x] مراجعة مطابقة/معاينة Excel قبل الاعتماد وتسجيل فشل الاستيراد.
- [x] جدول توصيل حسب المنطقة يشمل أيام التوزيع ووقت الإغلاق والحد الأدنى؛ يظهر حسب موقع الصيدلية في السعر والسلة ويدخل الحد الإقليمي في حساب أفضل سلة.
- [x] استعادة النسخة بعد معاينة وقائمة تحقق وإقرار أخذ نسخة احتياطية؛ يسجل إنشاء النسخة والاستعادة ومنفذهما.
- [x] الدفعات السعرية الكبيرة (50–248 صفًا) تنتظر موافقة مدير ثانٍ ويعرض له كامل الصفوف؛ 2–50 صيدلية يمكن إرسال تعليقها الجماعي للمراجعة، ولا يحدث التغيير قبل القبول.
- [x] قواعد وفهارس خاصة بـv25 ومسار نشر `/v25/` دون استبدال ملفات v24 أو تعديل إعداد نشر Firestore.

## تحقق مطلوب قبل الاستخدام
- [ ] تشغيل `npm run lint` و`npm run build` بعد أحدث التعديلات.
- [ ] مراجعة وتشغيل اختبارات Firestore Rules في Emulator، ثم التحقق من Actions والرابط المنشور بعد push.
- [ ] دمج قواعد وفهارس v25 مع إعداد Firebase الفعلي ونشرها يدويًا؛ الموقع وحده لا ينشرهما.
- [ ] اختبار الموافقات وسجل النشاط واستعادة النسخة في مشروع Firebase مرحلي/Emulator، لا على الإنتاج.

## قيود معلنة
- سجل التدقيق مكتوب من التطبيق ويخضع لقواعد Firestore، وليس سجلًا مشفرًا غير قابل للتلاعب أو بديلًا عن تدقيق خادمي مستقل.
- مسار الاستعادة يعرض معاينة وقائمة تحقق ولا يحذف، لكنه قد يستبدل سجلات لها المعرف نفسه؛ لا توجد بيئة اختبار مستقلة منشأة آليًا.
- استيراد الصيدليات يحدّث ملفات مستخدمين قائمة ولا ينشئ حسابات Firebase Authentication.
- لا تُقبل الدفعات السعرية التي تتطلب موافقة ثانية فوق 248 صنفًا؛ تقسم إلى دفعات أصغر حتى تكون الكتابة ذرية.
