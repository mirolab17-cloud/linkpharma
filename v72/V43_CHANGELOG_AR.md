# Link Pharma v43

## ما تم تغييره

تم إنشاء v43 كنسخة مستقلة من v42، مع تحديث هوية الحزمة إلى `linkpharma-v43` والإصدار `43.0.0`، وتحديث هوية PWA إلى `/linkpharma/v43/`، وإضافة بناء v43 إلى GitHub Actions.

### إصلاح أول تسجيل Google

المستخدم الجديد عبر Google ينشأ الآن بحالة `trial`، ومدة تجربة مأخوذة من إعداد الإدارة مع حصرها بين يوم واحد و31 يوماً، وتكون قيمة `trialDays` مطابقة للمدة. حساب المدير يحتفظ بالمسار الإداري السابق. لا يتم ابتلاع خطأ إنشاء الملف الشخصي؛ يحاول النظام الحفظ مرة ثانية بعد تأخير قصير، ثم يعرض رسالة عربية واضحة ويوقف حالة الدخول المؤقتة إذا فشلت المحاولتان.

### حماية Snapshot الأسعار

إعادة بناء Snapshot تستخدم الأسعار الظاهرة فقط عبر `includeHidden=false` و`filterVisiblePrices`. كما ترشح Cart أي سجل مخفي دفاعياً قبل استخدام Snapshot. وأضيفت حماية ثانية في قواعد Firestore تشترط أن يكون قارئ chunks الأسعار صيدلية نشطة ذات اشتراك فعال، مع احترام `allowedSuppliers`، ومنع المندوب والمستخدم غير المسجل والصيدلية المنتهية.

أضيفت اختبارات قواعد تغطي المندوب، والصيدلية النشطة للمستودع المسموح، ورفض المستودع غير المسموح، والصيدلية منتهية الاشتراك، والمستخدم غير المسجل. كما أصبح اختبار التسجيل يثبت أن الاشتراك النشط لا يقبل التسجيل الذاتي وأن trial القصير هو المسار المقبول.

### التقادم وإعادة البناء الجزئي

تحمل Meta الآن أوقات آخر Snapshot لكل مستودع. عند اكتشاف أن `supplier.lastPriceUpdate` أحدث من Snapshot، تقرأ صفحة الأسعار أسعار ذلك المورد مباشرة من Firebase بينما تستخدم Snapshot لبقية الموردين. أضيفت `rebuildSupplierSnapshot(supplierId)` لإعادة بناء chunks المورد فقط، وتُستدعى بعد rollback الإداري. كما يعرض مركز الإدارة تنبيهاً للموردين المتقادمَين، ويوفر تحديثاً سريعاً، ويحاول الإصلاح الصامت عند دخول المدير.

بعد نجاح كتابة Meta الجديدة، تحذف إعادة البناء الكاملة chunks الأقدم من آخر نسختين ضمن دفعات لا تتجاوز 390 عملية. وعند تحديث الكاش يحذف مفاتيح Snapshots القديمة غير المطابقة للنسخة الحالية. لم يتغير التحقق الحي في `getVerifiedOrderItems`.

### تحديثات سلسلة التوريد وWorker

تم استبدال SheetJS القديم بالنسخة الرسمية `xlsx-0.20.3` من حزمة CDN المطلوبة، وتحديث Vite إلى `8.3.5`. أضيف override يرفع `@grpc/grpc-js` إلى نسخة مصلحة، وأصبح `npm audit --omit=dev` بدون ثغرات مسجلة في v43.

تمت إزالة `setInterval` من Worker، ونقل تنظيف rate limiter إلى مسار `checkRateLimit` المتوافق مع Cloudflare Workers. أضيف متغير `ALLOWED_ORIGIN` إلى `wrangler.toml` مع بقاء المطابقة الدقيقة للأصل.

## ما لم يُنفذ

خيار `requireApproval` للصيدليات الجديدة لم يُفعّل في v43؛ بقي السلوك الحالي كما هو لأن المطلوب جعله اختيارياً ومطفأ افتراضياً، ولأن تفعيله يحتاج قراراً تشغيلياً واضحاً حول حالات pending ورسائل الموافقة. يمكن إضافته لاحقاً دون تغيير مسار trial الحالي.

لم تُنشر قواعد Firestore تلقائياً. يجب على مالك المشروع نشر `v43/firestore.rules` يدوياً من Firebase Console أو Firebase CLI قبل تفعيل النسخة الحية، لأن GitHub Pages ينشر ملفات الواجهة ولا ينشر قواعد Firestore.

## التحقق

نجحت الفحوصات التالية في v43:

- `npm run lint`
- `npm run build`
- `npm run test:rules:emulator` — 17 حالة ناجحة
- `node --check worker.js`
- `npm audit --omit=dev` — لا توجد ثغرات مسجلة

لم يتم تعديل مجلدات الإصدارات v1 إلى v42. التعديل خارج مجلد الإصدار اقتصر على إضافة v43 إلى سير عمل النشر وإصلاح `worker.js` و`wrangler.toml` المشتركين.
