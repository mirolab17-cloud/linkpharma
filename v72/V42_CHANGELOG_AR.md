# Link Pharma v42 — Firebase Catalog Snapshots

## المنجز

- أصبحت Firebase المصدر الوحيد للبيانات في هذا الإصدار؛ تم الاستغناء عن Google Sheets بالكامل.
- أضيفت نسخة مجمعة versioned للكتالوج والأسعار عبر `catalog_meta/current` و`catalog_snapshots`.
- تقسم البيانات إلى أجزاء تضم عدة صفوف، ما يقلل عدد قراءات مستندات Firestore عند فتح صفحة الأسعار.
- صفحة أسعار الصيدلية تقرأ Snapshot المنتجات، مع fallback إلى المسار السابق إذا لم تُبنَ نسخة بعد.
- السلة تستخدم Snapshot الأسعار عند التحميل العام، مع بقاء التحقق المباشر من أسعار الأصناف المحددة عند إنشاء الطلب وإرسال واتساب.
- أضيف كاش محلي مرتبط برقم النسخة وحجمه محدود حتى لا تعاد قراءة الكتالوج عند كل فتح للمنصة.
- بعد استيراد الأسعار أو الكتالوج يحاول النظام إعادة بناء Snapshot تلقائياً، وتوجد صفحة إدارية لإعادة البناء يدوياً.
- أضيفت قواعد Firestore تمنع الكتابة إلا للمدير، وتقصر Snapshot الأسعار على الصيدليات النشطة ذات الاشتراك والمستودعات المسموحة.
- أضيفت صفحة الإدارة `/admin/catalog-snapshots` ورابطها إلى الشريط الإداري.

## ملاحظة تشغيلية

بناء Snapshot لا يلغي مجموعة `prices` الأصلية. هذه المجموعة تبقى المصدر الموثوق للتحقق النهائي قبل الطلب، كما يبقى fallback متاحاً إذا كانت النسخة المجمعة غير موجودة أو فشل الوصول إليها. النسخ القديمة لا تُحذف تلقائياً في v42 حتى لا نفقد إمكان التراجع أو التدقيق.

## الفحوصات

نجح `npm run lint` و`npm run build` و`npm run test:rules:emulator`، ونجحت 16 حالة من اختبارات قواعد Firestore الحالية.
