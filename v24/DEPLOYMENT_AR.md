# نشر v24

## نشر الموقع

يحتوي `.github/workflows/deploy.yml` في جذر المستودع على خطوة بناء v24 ونسخها إلى `dist/v24/`. بعد دفع التغييرات إلى `main`، راقب سير عمل **Deploy to GitHub Pages**. عند نجاحه، ستكون النسخة على المسار `/linkpharma/v24/` أو مسار GitHub Pages المطابق لإعدادات المستودع.

## قواعد Firestore

قواعد v24 موجودة في [`firestore.rules`](./firestore.rules). لم تُنشر تلقائيًا؛ جذر المستودع لا يتضمن `firebase.json` ولا `.firebaserc`، كما لم يتم استخدام اعتماد Firebase أو الكتابة إلى قاعدة الإنتاج أثناء التطوير. قبل استخدام مزامنة القوالب وتعديل الطلبات، يجب مراجعة هذه القواعد ودمجها في ملف القواعد الفعلي لمشروع Firebase ثم نشرها من بيئة موثوقة ومهيأة لذلك. لا تستبدل قواعد الإنتاج كاملةً بهذا الملف دون مراجعة الفروقات؛ ادمج فقط قواعد `pharmacy_templates` وتحديث `orders` مع بقية قواعد المشروع.

## استيراد الصيدليات واستعادة النسخ

استيراد جدول الصيدليات يتطلب سجلات حسابات مصادقة قائمة، ويجب أن يتضمن كل صف `UID` و`Email`. المستخدمون الجدد يبدأون بحالة معلّقة، ولا ينشئ الاستيراد كلمة مرور أو حساب Firebase Authentication. استعادة النسخة تتطلب دور مدير وتدمج السجلات حسب معرّفاتها، وقد تستبدل الموجود المطابق للمعرف؛ لا تحذف سجلات، لكنها تتطلب نسخة احتياطية سابقة ومراجعة المعاينة.
