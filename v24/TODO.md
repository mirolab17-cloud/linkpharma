# نتائج الإصدار v24

## المنجز

- استعادة شاشة الدخول ومنطق Google popup-first من مصدر v21 (`v19`) داخل v24.
- إصلاح تحميل أسعار لا نهائي: طلب صفحات متتابعة، منع تكرار الطلبات، وزر يدوي احتياطي.
- عرض أرخص ثلاثة عروض ظاهرة لكل صنف افتراضيًا، مع خيار استعراض باقي الموردين.
- تحديد/إخفاء/إظهار أسعار مورد بالجملة أو لصنف محدد، مع سجل نشاط.
- ضبط «أفضل سلة» للسعر الفعلي بعد البونص والحد الأدنى ورسوم توصيل المورد الاختيارية، وإبقاء البونص عند إعادة تسعير البنود.
- مزامنة قوالب الصيدلية حسب UID، وإضافة «حفظ القائمة» لسلة المشتريات واستعادتها من حساب الصيدلية.
- تعديل الطلبية قبل تأكيد المستودع؛ حفظ البنود والأسعار السابقة والجديدة وعرض سجل الحالة/التعديل. مرشح الإدارة يعرض الحالات الخمس، والتنبيه يوضح أن فتح واتساب لا يثبت استلام المستودع.
- تسجيل تدقيق تغييرات الصلاحيات/الحالة وقائمة الموردين، إضافة إلى أنشطة الطلبات والأسعار المتاحة.
- تنفيذ معاينة فعلية واستيراد ملفات CSV/XLSX لملفات الصيدليات الموجودة في Firebase Authentication (UID وEmail إلزاميان). المستخدم الجديد يبدأ «معلقًا»؛ الاستيراد لا ينشئ كلمة مرور أو حساب مصادقة.
- تحسين استيراد الأسعار: كشف أعمدة الاسم والتركيز والشكل والعبوة والشركة، وحفظها بقالب خاص بالمورد؛ تخزين حجم العبوة مستقلاً وإظهاره في بطاقة السعر، مع استخدام خصائص الدواء للمطابقة التقريبية والمراجعة.
- توسيع النسخة الاحتياطية لتشمل الأسعار المخفية والطلبات والمواد الفعالة وسجل الأسعار ودفعات الاستيراد وسجل النشاط؛ معاينة الاستعادة وتقرير الإضافة/الاستبدال، ودمج لا يحذف البيانات.
- مسار PWA `/v24/` وخط بناء ونشر GitHub Pages للإصدار الجديد.
- نجاح `npm run lint` و`npm run build` محليًا بعد التغييرات السابقة؛ يلزم إعادة الفحص بعد آخر تعديلات ثم مراجعة نتيجة GitHub Actions.

## ملاحظات ونقاط متبقية

- لم يتم توحيد لوحة الإدارة ومركز القيادة في شاشة واحدة؛ بقيت الأقسام الحالية موزعة.
- قواعد Firestore داخل `v24/firestore.rules` تحتاج مراجعة ودمجًا ثم نشرًا يدويًا في مشروع Firebase. المستودع لا يحتوي `firebase.json`/`.firebaserc` ولم تُجر كتابة إلى قاعدة الإنتاج.
- لتعارض أيام توصيل الموردين حسب المنطقة، يلزم جدول مستقل لكل مورد ولكل محافظة/مدينة، مع نافذة/أيام التسليم، ثم عرض يوم التسليم القادم في شاشة المورد والسلة بعد اختيار موقع الصيدلية. لا تكتفِ بحقل واحد عام للمورد.
- المطابقة الدوائية تقريبية وتظل بحاجة إلى مراجعة صيدلي للحالات الملتبسة؛ لا يُقترح بديل علاجي تلقائيًا.
- لم يكتمل اختبار قبول حي مع Firebase والمتصفح. النسخة المنشورة تعتمد على نجاح GitHub Actions.
- إعادة الاستعادة قد تستبدل سجلًا ذا المعرف نفسه؛ يلزم أخذ نسخة احتياطية ومراجعة المعاينة قبل التنفيذ.
