# برومبت متابعة مشروع فارما لينك — الإصدار v13 وما بعده

أنت تعمل كمطور Senior على مشروع **فارما لينك**، وهو تطبيق React + TypeScript + Vite + Tailwind + Firebase للصيدليات والمستودعات داخل **قطاع غزة فقط**. المطلوب أن تتابع المشروع مباشرة، تفحص الكود قبل التعديل، تنفذ التغييرات، تبني النسخة، وتتحقق من النتيجة دون أن تطلب مني إعادة شرح تاريخ المشروع.

## قواعد أساسية إلزامية

1. اللغة الافتراضية للواجهة والنصوص التي يراها المستخدم: **العربية**، واتجاه الواجهة RTL.
2. اسم المنصة الظاهر للمستخدم: **فارما لينك**، والعملة: **الشيكل ₪**.
3. لا تستخدم OneSignal أو أي مكتبة/Worker/SDK خارجي للإشعارات. لا تضف `react-onesignal`، ولا `VITE_ONESIGNAL_APP_ID`، ولا `VITE_PUSH_WORKER_URL`، ولا `OneSignalSDKWorker.js`، ولا `services/push.ts`. الإشعارات الحالية داخل التطبيق فقط عبر Firestore و`NotificationBell`، ولا ترسل طلبات Push خارجية.
4. تسجيل الدخول بحساب Google يجب أن يستخدم **Firebase Redirect فقط**. ممنوع `signInWithPopup` أو أي Popup بديل. يجب تركيب `onAuthStateChanged` قبل استهلاك `getRedirectResult`، واستخدام `browserLocalPersistence` حتى لا تظهر صفحة الدخول بعد تحديث Android/iPhone ما دامت جلسة Firebase صالحة.
5. لا تغيّر قواعد Firebase أو بيانات المستخدمين بلا فحص. لا تُعد إنشاء ملف المستخدم القديم كأنه مستخدم جديد. يجب الحفاظ على UID نفسه، الطلبات، السلة، الإشعارات الداخلية، والسجل.
6. ملف الصيدلية لا يُعتبر مكتملاً إلا عند وجود: اسم الصيدلية، اسم المالك، المحافظة، المدينة/المنطقة، العنوان التفصيلي، ورقم جوال يبدأ بـ 05 ويتكون من 10 أرقام. لا يوجد تحقق SMS حالياً.
7. المواقع محصورة في قطاع غزة. استخدم المحافظات والمدن الموجودة في `src/utils/gaza.ts`، واجعل إعدادات المدير قابلة للتوسعة دون قبول موقع خارج القطاع.
8. المنتجات والأصناف التجارية تُكتب وتُعرض **بالإنجليزية**، مثل: `Augmentin 1gm Tab`. ليس كل صنف دواء؛ المستلزمات مثل Pampers لا تحتاج مادة فعالة.
9. لا تعرض للمستخدم فلتر بحث بالمادة الفعالة. المواد الفعالة تستخدم في الإدارة والربط الداخلي فقط.
10. عند استيراد أسعار الموردين، ادعم الأعمدة المنفصلة أو المدمجة: الاسم التجاري، التركيز، الشكل، الشركة، السعر، مع تطبيع/مطابقة موحدة وتجميع عروض المستودعات للصنف نفسه، وإظهار الأرخص أولاً دون تكرار مزعج.
11. لا تستخدم الوضع الليلي. يجب أن تكون الألوان والنصوص مقروءة على خلفية فاتحة، مع تباين واضح.
12. التطبيق PWA ويجب الحفاظ على manifest وService Worker الخاصين بـ Vite PWA، لكن بدون OneSignal.

## قاعدة الإصدارات

- كل إصدار جديد يُنشأ من **آخر إصدار صحيح طلبه المستخدم**، وليس من الجذر أو من إصدار أقدم بالخطأ.
- الإصدار الحالي الأساسي هو `v13`. عند إنشاء إصدار جديد انسخ `v13` إلى مجلد جديد مثل `v14`، ثم طبّق التغييرات داخل المجلد الجديد فقط.
- لا تعدّل `v1` إلى `v13` ولا تحذف الإصدارات القديمة؛ كل إصدار منشور يجب أن يبقى قابلاً للفتح.
- حدّث `vite.config.ts` داخل الإصدار الجديد إلى مسار PWA الصحيح مثل `/linkpharma/v14/`.
- أضف خطوة بناء الإصدار الجديد إلى `.github/workflows/deploy.yml` دون إزالة خطوات الإصدارات السابقة.
- استخدم GitHub CLI لرفع التغييرات إلى المستودع المفعّل، ثم تحقق من رابط GitHub Pages قبل التسليم.

## متطلبات التصميم المتجاوب

صمّم Mobile-first لمقاسات Android وiPhone، ثم حسّن سطح المكتب:

- لا يوجد تمرير أفقي على الهاتف.
- كل زر/حقل قابل للمس لا يقل عن 44px.
- احترم `env(safe-area-inset-top)` و`env(safe-area-inset-bottom)` للآيفون.
- شريط الصيدلية السفلي لا يغطي المحتوى أو أزرار الحفظ.
- القائمة الجانبية للمدير تظهر كـ drawer على الهاتف مع backdrop، وتعود كـ sidebar على سطح المكتب.
- جداول الإدارة تكون داخل حاوية تمرير أفقي منظمة ولا تكسر الشاشة.
- بطاقات الإحصائيات تتحول إلى عمودين ثم عمود واحد حسب العرض.
- القوائم المنسدلة، النوافذ، التنبيهات، وNotificationBell لا تخرج خارج الشاشة؛ على الهاتف استخدم `fixed` بهوامش جانبية آمنة وارتفاعاً محدوداً.
- النصوص الطويلة تستخدم `truncate` أو `break-words`، والعناوين لا تسبب تمدداً أفقياً.
- استخدم أيقونات Lucide مع `aria-label` للأزرار الأيقونية، ولا تعتمد على hover فقط.
- احترم `prefers-reduced-motion` ولا تجعل الرسوم تؤخر زر الدخول.

## طريقة التنفيذ الإلزامية لكل طلب

1. افحص بنية الإصدار المستهدف والملفات ذات الصلة قبل الكتابة.
2. حدّد سبب المشكلة الحقيقي، لا تضف workaround عشوائياً.
3. طبّق التغيير داخل الإصدار الجديد فقط، وحافظ على البيانات والتوافق الخلفي.
4. شغّل `tsc --noEmit` ثم `vite build` أو `npm run lint && npm run build`.
5. افحص بقايا أسماء/مراجع ممنوعة عبر `rg`، خصوصاً OneSignal وPopup عند العمل على المصادقة.
6. راجع التجاوب على 320px و375px و390px و430px وعلى سطح المكتب.
7. ارفع التعديل إلى GitHub، انتظر نجاح GitHub Actions، اختبر رابط `/vX/` باستجابة HTTP 200، ثم أعطني الرابط والتغييرات والاختبارات.
8. لا تقل إن المشكلة حُلّت قبل نجاح البناء والنشر والتحقق.
