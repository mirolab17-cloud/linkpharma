# متطلبات LinkPharma v37

## مزامنة البيانات وتقليل القراءات
- [x] استخدم listeners مشتركة للكتالوج؛ بعد snapshot البداية تطبق `docChanges()` الإضافات والتعديلات والحذف أثناء اتصال الجلسة، مع الاستفادة من cache Firestore الدائم.
- [x] أبقِ الأسعار مقيدة بالأصناف الظاهرة والموردين المصرح بهم، ومفاتيح cache مرتبطة بالحساب والصلاحيات وقائمة الأصناف.
- [x] لا تُعرض الأسعار من fallback محلي عند `permission-denied`؛ يعاد الخطأ بدلاً من تجاوز تحقق Firestore.

## صفوف استيراد الأسعار والأسماء البديلة
- [x] تحرير قيم صف Excel قبل المطابقة: الاسم، التركيز، الشكل، العبوة، الشركة، السعر، البونص والباركود.
- [x] البحث عن صنف المنصة عند الربط مع إظهار الاسم والتركيز والشكل والعبوة والشركة.
- [x] تعديل الصنف المرتبط وحفظه مع بقاء `productId` نفسه، ثم تحديث اقتراحات الصفوف.
- [x] حفظ الاسم الأصلي للمورد كاسم بديل دائم خاص بالمورد والصنف والهوية؛ التحميل يسبق المطابقة، والربط الآلي لا يقع إلا للمرشح الوحيد المتوافق.
- [x] منع اعتماد التطابق التقريبي أو الغامض تلقائياً، واستنتاج التركيز الرقمي من الاسم عندما يغيب عمود التركيز.
- [x] الاحتفاظ بتقدم الدفعات ورسائل أخطاء Firestore بدلاً من نجاح محلي غير مؤكد.
- [x] تسجيل حالة وعدد الصفوف المكتوبة مع كل chunk؛ تظهر الدفعة الجزئية كغير مكتملة ويمكن استكمال rollback لها بدلاً من ترك أسعار بلا سجل.
- [x] تنفيذ rollback بمعاملات تحقق السعر والتاريخ ذرّياً مع lease مملوك يمنع تراجعاً متزامناً أو استبدال سعر أحدث.
- [x] إبقاء tombstone بحالة rolled_back ومنع القواعد لأي chunk متأخر من إعادة إنشاء سجل الدفعة.

## إدارة المواقع والفروع وعناوين الصيدلية
- [x] محرر عربي هرمي لإضافة/تعديل/حذف المحافظة والمدينة والشارع بدلاً من إدخال JSON.
- [x] إدارة عدة فروع واختيار فرع افتراضي؛ كل فرع مرتبط بالقاموس وعنوان تفصيلي.
- [x] اشتراط اختيار المحافظة والمدينة والشارع وكتابة العنوان التفصيلي قبل حفظ ملف/فرع جديد.
- [x] اختيار فرع التسليم في السلة وحفظ لقطة العنوان والهاتف للطلب الجديد، دون تعديل الطلبات القديمة.
- [x] إبقاء قراءة `gazaLocations` والعناوين القديمة متوافقة مع ظهور تنبيه للترقية الاختيارية إلى فروع.
